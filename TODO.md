# Ledger AI — Product outcomes

- [x] **Chat-first agent workspace and expandable tool calls** — The initial view is the chat window. Agent tool calls appear as distinct clickable tiles or buttons; clicking one opens its details in a full-screen view. The experience is minimal, professional, and easy to use.
- [x] **AI chat with hidden provider/model details** — Use the configured `NVIDIA` secret for server-side chat. Use the standard chat model by default; when the user selects the neutral **Vision** control, route that request to the vision-capable model. Place Vision at the right of the chat composer and immediately left of Send. Do not show provider or model names in the interface. Validate the `NVIDIA` token; show no success toast, and show an error only if validation or a request fails. Preserve filesystem tool use and approvals. Deploy publicly without login.
- [x] **Unrestricted, bounded file attachments** — Add an attachment control. Accept all file extensions and types with no extension filter; allow up to 50 files, each up to 10 MB. Store user attachments in Wasmer’s persistent `Upload/` folder beside `Project/`, and make the attachments available to the AI request, including images when Vision is selected.
- [x] **Project-scoped filesystem and CRUD without a terminal** — Provide file-system tools only; do not include a terminal yet. Users have full create, read, update, and delete control over projects. A project is a parent folder whose codebase is stored within that folder. Each created project gets a dedicated, safely named folder under the sandboxed `Project/` directory, and its folders and files appear in the project. Agent-initiated project renames and deletions of projects, files, or folders pause for explicit approval. Unsaved editor changes are protected by a save/discard prompt and retained when an agent edits the open file.
- [x] **Hamburger file explorer with VS Code-style file icons** — A hamburger control on the left reveals or hides the file list. Show the project tree with icons based on programming language in a VS Code style.
- [x] **Monaco code editing and Markdown/image rendering** — Build a Monaco editor and a Markdown renderer. Render Markdown agent responses and Markdown files. When the agent calls an image or returns Markdown with `[label](link)`, render the photo in a modal under the response or open the Markdown file with an appropriate file icon.
- [x] **Left sidebar tabs and project tiles** — Include the file tree and Projects as two tabs in the left sidebar. When Projects is selected, list the available projects as vertically taller tiles, but not excessively oversized. Add a plus icon at the top-left inside the Projects tab so the user can create projects there.
- [x] **Wasmer persistent storage** — Ensure projects are persisted under Wasmer permanent storage. Verified by creating a disposable project and confirming both it and its README survived a Wasmer redeployment on the existing `ledger-projects` volume mounted at `/data`.
- [x] **Brand icon and polished, visual-first interface** — Create a distinct abstract icon for Ledger AI. Make the app simple to use, polished, and more visual than textual; remove unnecessary text and jargon.
- [x] **Comfortable dark and light themes** — Provide dark and light modes. Give the light mode extra polish and a comfortable darkened-white/cream base, using the supplied Black (`#000000`) and Blanche Diamond (`#F6E9C7`) colors rather than an ordinary bright-white theme. Keep the dark mode balanced and not overly dark or depressing. Use the supplied selected colors more prominently throughout the brand.
- [x] **Ergon tool/skill review and gated design** — Review the public Ergon server tool and skill components. Preserve the existing project-scoped filesystem, document each component's disposition in `ERGO_TOOL_REVIEW.md`, and prepare a separate gated design for Git, shell/process, external MCP, and scheduling. Do not expose privileged tools in the public no-login app pending authentication, isolation, approvals, safeguards, and separate product approval.
- [x] **Ergon filesystem-tool mapping** — Implement the existing Ergon filesystem module's `read`, `write`, `edit`, `ls`, `cat`, and `glob` behaviors in Ledger AI's existing Wasmer server files. `read` accepts a relative file path and optional 0-indexed line `offset` and `limit`, and returns the total line count. `write` creates or overwrites a file. `edit` replaces exact `oldString` with `newString`, replacing all only when `replaceAll` is true and rejecting missing or ambiguous matches. `ls` lists up to 1,000 immediate entries with names and file/directory/other types, and indicates when the result is truncated. `cat` is a read alias. `glob` finds paths by a relative pattern (`*`, `**`, `?`) and optional relative `cwd`. Confine every operation to the active project's `Project/<id>/` root; preserve path traversal and symlink protections; skip `.git`, `node_modules`, and Ledger metadata; enforce the existing 1.5 MB file limit and bounded traversal by entry count/depth; do not add terminal/process execution, a new runtime module, or a package setup step.
